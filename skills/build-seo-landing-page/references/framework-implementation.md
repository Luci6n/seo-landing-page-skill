# Framework Implementation Notes

Use this when adapting the landing-page skill to static HTML, React/Vite, Next.js, Astro, or a CMS.

- Static HTML

## Universal Rules

- Keep important content crawlable in the initial HTML or server-rendered output.
- Use the framework's native metadata, routing, sitemap, and image features when they exist.
- Keep `robots.txt`, `sitemap.xml`, favicons, manifest, and public images in the framework's public/static asset folder.
- Do not add a heavy framework to a simple static page unless the project needs it.
- Measure the built output with Lighthouse/PageSpeed instead of judging by framework name.

## Static HTML

Put these directly in `index.html`:

- `<title>`
- meta description
- canonical
- Open Graph and Twitter metadata
- favicon and manifest links
- JSON-LD scripts

Keep assets in stable public paths such as:

```text
assets/
favicon.ico
site.webmanifest
robots.txt
sitemap.xml
```

Use static HTML when the page is simple, content-heavy, and does not need a build step.

## React/Vite

Common structure:

```text
src/
+-- App.jsx
+-- main.jsx
+-- components/
+-- data/
+-- styles/
public/
+-- robots.txt
+-- sitemap.xml
+-- site.webmanifest
+-- assets/
```

Implementation guidance:

- Put simple global metadata in `index.html` when the app has one route.
- Use a head manager only if routes need dynamic metadata.
- Keep public assets in `public/`; reference them from root paths.
- Generate or update sitemap manually for small static apps.
- Avoid client-only rendering for business name, services, address, phone, and FAQ content when SEO matters.

## Next.js App Router

Common structure:

```text
app/
+-- layout.tsx
+-- page.tsx
+-- sitemap.ts
+-- robots.ts
+-- globals.css
components/
public/
+-- assets/
+-- favicon.ico
```

Implementation guidance:

- Use `metadata` or `generateMetadata` for titles, descriptions, canonical, Open Graph, and Twitter metadata.
- Put `themeColor`, `colorScheme`, and viewport settings in the separate `viewport` / `generateViewport` export, not in `metadata` — they moved there in Next.js 14. When adapting `templates/metadata-head.html`, the `theme-color` meta tag becomes `viewport.themeColor`, not a `metadata` field. A `metadata-to-viewport-export` codemod exists for older projects.
- Use `app/sitemap.ts` and `app/robots.ts` when routes are generated by the app.
- Put JSON-LD in the page or layout using a script tag with `type="application/ld+json"`.
- Prefer server components for content-heavy landing sections.
- Use client components only for actual interactivity.
- Check static export limitations if deploying to static-only hosting.

## Astro

Common structure:

```text
src/
+-- pages/
+-- components/
+-- layouts/
+-- data/
+-- styles/
public/
+-- robots.txt
+-- sitemap.xml
+-- site.webmanifest
+-- assets/
```

Implementation guidance:

- Use layouts for shared metadata and JSON-LD.
- Keep interactive islands small.
- Prefer static output for simple marketing pages.
- Use sitemap integration or generate sitemap during build.

## WordPress Or CMS

Use CMS-native controls when non-developers will edit content.

Check:

- SEO plugin metadata.
- Schema settings.
- Sitemap generation.
- Image optimization.
- Caching.
- Redirects.
- Backup and update process.

Do not duplicate conflicting metadata between theme code, page builder settings, and SEO plugins.

## Common Mistakes

- Updating visible copy but forgetting metadata and structured data.
- Setting canonical to the staging URL.
- Leaving `noindex` after launch.
- Shipping huge JavaScript for a simple landing page.
- Hiding all content until client hydration.
- Forgetting to update sitemap and `lastmod`.
- Referencing assets from paths that break after build.
